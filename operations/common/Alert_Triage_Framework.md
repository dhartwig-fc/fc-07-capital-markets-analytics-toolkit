# Capital Markets Alert Triage Framework

## Framework Purpose

The Capital Markets Alert Triage Framework defines how generated market-surveillance
alerts are prioritised, routed and reviewed by surveillance investigators.

It translates exposure scores, typology severity, materiality and contextual risk indicators into operational priority levels.

This framework supports:

- Alert prioritisation
- Investigator workload management
- Escalation decisions
- Scenario calibration
- Operational performance monitoring

---

## Triage Workflow

```text
Alert Generated
  ↓
Exposure Score Assigned
  ↓
Triage Factors Applied
  ↓
Priority Level Determined
  ↓
Investigator Queue Assignment
  ↓
Case Review
  ↓
Outcome Captured
  ↓
Feedback to Calibration
```

---

## Triage Inputs

| Input | Description |
|------|-------------|
| Exposure Score | Composite score generated by the analytic's scoring model |
| Typology | Capital-markets surveillance scenario that triggered the alert (CM001–CM010) |
| Order/Trade Behaviour Deviation | Strength of the deviation from normal order-flow or trading behaviour |
| Counterparty Exposure | Risk carried by counterparties, brokers or ultimate owners |
| Venue/Jurisdiction Risk | Trading venue or corridor exposure |
| Network Linkage | Shared account, beneficial owner or entity exposure with known bad actors |
| Order/Trade Velocity | Speed and pattern of order placement, amendment or execution |
| Historical Alerts | Previous alerts or suspicious activity |
| Investigator Capacity | Available operational review capacity |

---

## Priority Bands

| Priority | Score Range | Operational Treatment |
|----------|-------------|----------------------|
| P1 Critical | 81–100 | Immediate review and escalation |
| P2 High | 61–80 | Investigator review within standard SLA |
| P3 Medium | 31–60 | Review where capacity allows or if combined with other indicators |
| P4 Low | 0–30 | Monitor, suppress or batch review |

---

## Triage Rules

| Rule | Condition | Priority Impact |
|------|-----------|----------------|
| Rule 1 | Exposure score above 80 | Set priority to P1 Critical |
| Rule 2 | Confirmed link to a known manipulation network | Set priority to P1 Critical |
| Rule 3 | Exposure score 61–80 | Set priority to P2 High |
| Rule 4 | Flow reaches a designated or high-risk counterparty/beneficial owner | Increase priority by one level |
| Rule 5 | High-risk venue or jurisdiction combined with material value | Increase priority by one level |
| Rule 6 | Repeat exposure alerts within 12 months | Increase priority by one level |
| Rule 7 | Weak behavioural deviation and no corroborating indicator | Decrease priority by one level |

## Queue Assignment

| Queue | Alert Type | Review Team |
|-------|------------|-------------|
| Critical Escalation Queue | P1 Critical alerts | Senior Surveillance Investigator / Market Abuse Escalations Team |
| High Risk Surveillance Queue | P2 High alerts | Trade Surveillance Investigator |
| Standard Review Queue | P3 Medium alerts | Market Abuse Investigator |
| Monitoring Queue | P4 Low alerts | Batch review / analytics monitoring |

## Example Triage Decision

| Field | Example |
|------|---------|
| Typology | CM003 – Spoofing |
| Subject | Trading account, non-bona-fide order flow linked to Zeta Commodities Ltd |
| Behaviour | Large cancel-before-execution ratio, opposite-side fills |
| Exposure Score | 74 |
| Network Linkage | No |
| Initial Priority | P2 High |
| Trades Ahead Of Known High-Risk Entity | Yes |
| Final Priority | P1 Critical |
| Rationale | High exposure score combined with a link to an entity already flagged elsewhere in the network |

## Feedback To Model Calibration

| Feedback Signal | Calibration Use |
|----------------|-----------------|
| High False Positive Rate | Increase thresholds or reduce weights |
| High STOR Conversion Rate | Preserve or strengthen scenario |
| Investigator Override | Review triage rule effectiveness |
| Repeat Weak-Exposure Alerts | Adjust minimum exposure threshold |
| Missed Behavioural Exposure | Add or increase behavioural-mismatch weighting |
| SLA Breaches | Adjust queue routing or prioritisation |

---

## Relationship To Scoring Framework

The triage framework does not replace an analytic's exposure scoring model.

The scoring model determines:

```text
How much market-abuse exposure does the alert carry?
```

The triage framework determines:

```text
How urgently should the alert be reviewed?
```

Example:

```text
Exposure Score: 74
Exposure Band: High
Initial Priority: P2 High

Trades Ahead Of Known High-Risk Entity: Yes
Repeat Behaviour: Yes

Final Priority: P1 Critical
```
